# 自动执行与回传

## 执行机与业务机器
入口在交付的「现场执行」，节点在「设置 → 执行节点」登记。执行位置有两种：集群内机器兼任执行，或独立管理机。独立管理机不计入业务节点数，不放置数据库角色、不初始化数据盘。新交付可在机器步骤选择位置；已有交付不能通过改节点 IP 直接搬迁执行位置，需要核对原项目、密码和软件源。
执行机当前须与交付目标选择相同 OS 版本和架构；接入页提供 Linux x64 二进制，不能声称支持其他架构。使用交付 bin/ansible-playbook、bin/ansible-inventory；没有 bin/ansible。
节点初次接入不要求填写未来集群和全部目标 IP。管理员在交付中授权，目标来自交付，不由 AI 自行扩大。令牌和私钥不得发给模型。
同一独立节点服务多集群时，每个集群独立软件源端口、项目和密钥；独立管理机的每个集群解包到 /root/middleware-executions/<集群标识>/middleware-automation，上传目录为 /tmp/mw-upload/<集群标识>；以本交付手册里的实际路径为准，在执行器 root / roots 登记。选择运行环境同时核对本集群路径和材料摘要，不能只因版本相同就换用其他集群目录。不能覆盖别的交付的环境和密码。

## 接入与准备
向导依次为「选择执行机器 → 检查接入与材料 → 确认执行范围」。接入心跳不等于可执行，必须验证执行机、目标身份、SSH 权限、运行环境和离线材料。检查十分钟有效，授权、接入身份、材料、执行器版本改变后重检。旧节点保留旧协议，不宣称旧的人工准备勾选是自动检查证据。
已有 root SSH：使用现场配置和已核验主机指纹，无需目标 Agent。
拿不到密码但能通过堡垒机安装：从交付逐台生成短期目标 Agent 配置，在对应主机核对名称/IP、通过现有堡垒机会话以 root 安装。Agent 主动连接平台，只配置指定执行机的专用公钥并返回主机公钥。私钥只留执行机，绝不复制到目标。首次准备检查生成公钥，等目标确认写入后重新检查。普通交付用户不能批准扩大信任。
目标 Agent 当前是 SSH 信任助手，不是无 SSH 执行引擎。需要目标可达平台、执行机可达目标 SSH；不修改 sshd、不开 root 登录、不导出堡垒机密码。禁止机器间 SSH 或目标无法直连平台时，本机执行/中继尚未开放，使用离线交付与日志上传；不得承诺安装 Agent 就能绕过客户策略。
部分 PG 跨机验收仍需要数据库节点间已批准的 SSH，这与执行机到目标的信任不同；前置检查失败时尚未开始数据库测试，不能扩大为全互信或分发私钥。
尚未注册的接入配置可直接取消并重新登记；已注册的机器撤销后须等目标 Agent 实际移除托管公钥才显示完成，其他 authorized_keys 条目保留。目标离线显示待撤销；已存在会话需现场核实。没有 Agent 心跳不能据此推断公钥已删除。

## 执行与证据
按原手册顺序仅执行已选步骤，失败停止，不自动重试或回滚数据库。启动前条件缺失显示「准备受阻，命令未启动」；可能已经运行但失联显示「现场状态待核实」，不得自动重派。
执行进程独立于网页和 Web 更新。断网时已授权步骤继续，结果在本地保存后补传；下一步必须再次取得授权。升级执行器自身前先停接单、处理当前步骤。
用 execution_history 查询、execution_log 读脱敏证据。报告保存当时的执行机位置、接入方式、准备检查、批次、尝试、快照、机器、时间、退出码与跟进项。日志导入、人工确认和执行节点验证必须分别标明；未执行、跳过或未知不能写成通过。
组件声明 automatic 必须通过 timeout、postconditions、expect 校验，inputs.timeout 不是执行时限。新能力不会自动授权旧交付。定时任务、云 ELB 自动操作、无 SSH 执行和现场中继均不得虚构。
