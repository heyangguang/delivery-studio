# 故障复盘报告

## 结构
1. **概述**：一两句话说明发生了什么、影响多大、现在的状态。
2. **时间线**：按时间列出关键事件（发现、判断、操作、恢复），用执行记录里的时间。
3. **现象与影响**：用户看到什么、哪些服务受影响、持续多久。
4. **根因**：直接原因和深层原因分开写；有证据的写证据，推测的标明"推测"。
5. **处理过程**：做了哪些操作、哪些有效、哪些无效。
6. **改进项**：每条记录已确认的负责人和期限，未提供时标待确认，不编造，分为：手册/组件要改的、监控要加的、流程要调整的。

## 写法
- 客观，不追责个人；用事实和数据。
- 命令和配置用代码块。
- 需要改交付手册的地方，在交付窗口里用提案提出，让用户确认。
