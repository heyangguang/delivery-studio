# 权限与 IAM（1.0.64-dev 起）

## 模型
- **权限点**：每个会改东西的按钮、每个不是人人都能看的页面，对应一个权限点（`iam.go` 的 `perms`，共 27 个，按 交付 / 安全 / 组件 / 软件库 / AI / 知识库 / IAM / 设置 分组）。
- **角色** = 一组权限点 + 数据范围（仅自己 / 所在团队 / 全部）。一个人可以有多个角色，权限取并集，范围取最大。
- **内置角色**（不能改，可复制）：系统管理员、交付工程师、安全管理员、组件维护者、只读审计员。
- **团队**：用户组。数据范围为「所在团队」的角色，能看到同团队成员的交付和方案；团队知识库也可以按团队划分。

## 检查方式
- 服务端在路由入口按 `routePerms`（接口 → 权限点）统一检查；**会改东西的接口如果没有登记权限，一律拒绝**，新加接口不会因为忘了登记而放开。
- 交付相关的可见范围统一走 `visibleJobs` / `jobVisible`；AI 读取交付时同样受它限制。
- 前端用 `can()` 决定显示什么：没有权限的页面入口和按钮一律隐藏。权限改动后，对方下一次请求就按新权限执行；切回页面时界面会刷新。

## 安全规则
- 只能授出自己有的权限、给出不超过自己的数据范围；拿走别人的角色也一样。
- 平台始终保留至少一个能「管理用户」且能「管理角色」的可登录账号。
- 授权、角色、团队的每次改动都写操作审计。

## 迁移
- 未在 IAM 里授过权的账号：原管理员 → 系统管理员，原交付使用者 → 交付工程师（仅自己）。升级后行为不变。

## 存储与接口
- `data/settings/iam.json`：自定义角色、团队、授权。
- `GET /api/iam`；`POST|PUT|DELETE /api/iam/roles[/id]`；`POST|PUT|DELETE /api/iam/teams[/id]`；`PUT /api/users/{name}/grant`；`/api/session` 返回权限点、范围、角色和团队。

## 删除账户（1.0.66-dev）
- IAM → 用户 → 删除。删掉：密码和登录、AI 对话、个人的技能 / MCP / 资料。保留：交付和方案、操作审计。
- 删除时可以把交付交给别人；没转交的，以后在「已删除的账户」里还能转交。删除过的用户名不能再用，避免新账号继承旧交付。
- 不能删自己；不能删掉最后一个能管理用户和角色的人；只能删除权限不超过自己的人。

## 操作审计（1.0.66-dev，在 IAM 里）
- 每个会改动的请求、每次下载和导出自动记一条：谁（账号、来源 IP、浏览器）、何时、资源（类型 / 编号 / 名称）、动作（动作名 + 方法和路径）、请求内容（参数和正文；口令、密钥、令牌、证书一律打码，上传文件只记文件名和大小，图片不记内容）、结果（成功 / 被拒绝 / 未通过 / 出错、HTTP 状态码、错误信息）、耗时。
- 被拒绝的请求也会记录。可以按时间、用户、资源、动作、结果筛选和全文搜索，导出 CSV。查看和导出审计本身也会被记录。
