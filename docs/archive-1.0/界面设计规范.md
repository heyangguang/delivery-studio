# 界面设计规范（Middleware Hub）

## 概览执行入口（1.0.149-dev）

- 使用中性底、细边框的两行入口；进度环只反映现场已记录的完成步数，不模拟部署进展。方案名称、状态与下一步操作保持明确，整行可点击。
- 待执行、执行中、材料生成、失败、步数已完成待回传分别给出对应入口；点击仍进入原方案，不直接触发现场执行。
- 悬停轻微抬升、箭头前移及按下回弹均使用变换，不挤动布局；键盘聚焦有清楚反馈，悬停或聚焦提前读取详情。减少动态效果时停用位移、过渡及加载旋转。
- 深浅色共用主题变量，窄屏保留进度与主要操作，省略后续可用操作的辅助说明。

## 新建与草稿（1.0.148-dev）

- 普通新建、从某份交付复制、各来源及意图的变更方案、明确指定的 AI 对话分别保存草稿，不再只按应用共享一份缓存。
- 有未完成配置时，在挂载表单及 AI 助手之前显示「继续填写 / 新建一份」选择。继续恢复字段、方案选择及步骤；新建清空该流程的草稿和本地 AI 关联，再挂载全新表单。其他应用和来源的草稿保留。
- 表单内保留明确的新建入口，清空前确认；取消时继续编辑当前内容。快捷搜索在当前新建地址再次发起新建时，也触发此入口。
- 提交请求失败保留草稿；请求被接收并创建交付记录后，先停止该表单和 AI 的本地保存，再清理对应草稿，避免异步响应写回旧内容。后续材料生成失败可从该交付记录重新生成。
- 旧缓存若已对应创建过的交付记录，进入普通新建时自动清理。恢复选择尚未作出时不启动旧 AI 对话。取消或卸载填表流程会中止流式请求与逐步填写动画。
- 草稿只保存配置与步骤，不保存证书私钥等上传文件；恢复后提示重新选择所需材料。损坏的本地草稿从空白开始，本地存储不可用时保留可编辑表单并显示保存异常。

## 集群配置（1.0.145-dev）

1.0.146-dev 调整：配置分类放在内容顶部，取消第三列侧栏；参数按连续分组排列，宽屏并排展示，来源说明收进页头，单一方案不显示无意义的来源下拉框。方案详情的「全部方案」返回入口放在内容区内，与标题及正文对齐，使用普通面包屑；取消右侧「更早 / 更新」分页。

集群详情在「概览」旁增加「配置」页签。概览的「查看配置」、每份方案的「查看这份方案的配置」都进入同一查看器。URL 保留集群、来源方案和分区，刷新、直接打开、浏览器返回都能恢复所在位置。

- **配置来源**：默认采用服务端返回的当前交付记录，可切换同集群的历史方案。清楚区分未回传的计划、已回传的当前记录、历史记录及作废方案；现场有偏差时保留回传说明，不把方案当成实测状态。
- **机器与角色**：主机名、地址、控制节点、数据盘和初始化选择，按机器列出组件角色；角色可直接进入对应组件的配置。
- **访问入口**：分别显示应用入口、外部负载均衡地址与监听端口、后端节点及端口、健康检查和组件监听端口。端口可以不同，不根据组件名称猜测。
- **组件参数**：按声明分组，中文名称与原始参数名并列；显示保存的值、是否已指定或生成时补全、未启用状态，支持逐项复制。当前组件 Schema 只用于补充名称和说明，不重算历史参数。说明读取失败时仍可查看原记录并重试。
- **搜索与原始规格**：在机器、IP、参数和值、访问入口之间搜索，结果可定位并聚焦到具体行。保留提交的 YAML 和生成配置 JSON；下载使用现有文件接口与下载权限。
- **呈现**：顶部分类与连续分区，不增加独立侧栏或 KPI 卡片。浅色、深色共用语义变量；窄屏分类横向滚动，长地址换行，原始文件单独滚动；键盘可操作分类、复制、搜索及页签，尊重减少动态效果。
- **异常状态**：首次载入骨架、空记录、无搜索结果、无效来源/分区、读取失败重试、离线与已读取数据提示。权限拒绝或记录被删除时移除缓存内容，不继续展示旧记录。

本文从现有前端 [frontend/src/](frontend/src/) 反向整理，记录已确认保留的界面风格、页面模式、组件和交互约定，并列出它与新平台模型（见《组件清单设计.md》）之间的差距。后续新页面、新组件按本文扩展，不另起风格。

数据来源：`theme.css`（设计变量）、`ui.tsx`（公共组件）、`main.tsx`（外壳）、`router.ts`、`shared.tsx`，以及各页面文件。

## 1. 技术栈与约束

| 项 | 取值 |
|---|---|
| 框架 | React 18.3.1 + TypeScript，`createRoot` |
| 组件库 | Arco Design 2.66.18（`@arco-design/web-react`），中文语言包 `zh-CN` |
| 构建 | Vite，`outDir` 为 `../store_assets`，由 Go 服务直接提供静态文件 |
| 路由 | 自写的哈希路由 `router.ts`（交付、新建、应用、组件、账户），不依赖路由库 |
| 状态 | 页面内 `useState`；跨页面只有 `App` 里的 `apps`、`jobs`、`user`，通过 props 下传；无全局状态库 |
| 运行环境 | 浏览器与服务器均不访问外网或 CDN，所有字体用系统字体栈 |

约束：

- 不引入第二套 UI 库。需要的新控件优先用 Arco，再用 `theme.css` 覆盖外观。
- 不引入外部字体、图标字体、统计脚本。图标用 Arco 内置 `@arco-design/web-react/icon`，插画用内联 SVG。
- 新页面必须在浅色、深色两种外观下都可用，颜色只引用 CSS 变量，不写死十六进制（例外：应用图标渐变，见 5.2）。

### 1.1 主流程

1. **应用目录**：看到已接入的应用、版本、支持的系统和架构、方案、离线材料是否齐全；材料不齐的应用显示为不可用并写明原因。
2. **选方案**：每个应用提供若干方案（如单节点、一主两从）；表单据此生成机器角色和数量，不允许任意删减高可用方案里的必要角色。
3. **填表单**：实例名称、机器、磁盘、访问网段、入口、证书、参数。默认值必须在预览里明确展示，不能悄悄替用户改输入。
4. **校验预览**：参数、重复地址、端口、角色约束、证书链与域名与密钥匹配、磁盘初始化选择、制品版本与哈希、将上传的文件。
5. **生成交付**：按机器下载材料，同时提供完整交付目录、校验文件和手册。失败要显示具体阶段，保留可查原因，**不发布不完整的交付**。
6. **现场执行**：免密准备 → 分阶段部署 → 内部测试 → 入口测试 → 测试资源清理。平台只生成材料，现场仍人工上传并按手册执行；生成成功不显示为部署成功。

## 2. 视觉语言

安静、偏苹果风格：中性灰底、白色面，只有一个靛蓝品牌色；用发丝线分隔，而不是层层套框；浮层使用毛玻璃；动效克制，使用弹簧曲线。

### 2.1 颜色变量

定义在 [theme.css](frontend/src/theme.css) 的 `body`（浅色）与 `body[arco-theme="dark"]`（深色）。

|---|---|---|---|
| `--bg` | #f5f5f7 | #0d0d0f | 页面底色 |
| `--surface` | #ffffff | #18181b | 卡片、输入框、弹层 |
| `--surface-2` | #fafafb | #1d1d21 | 侧栏、列表底 |
| `--sunken` | #f0f0f3 | #111113 | 下沉区、禁用输入 |
| `--ink` / `--ink-2` | #1d1d1f / #3a3a3c | #f5f5f7 / #d1d1d6 | 正文 / 次级正文 |
| `--mute` / `--faint` | #6e6e73 / #8e8e93 | #a1a1a6 / #7c7c82 | 说明文字 / 占位与弱提示 |
| `--line` / `--line-strong` | 黑 8% / 14% | 白 9% / 16% | 发丝线 / 控件描边 |
| `--hover` / `--press` | 黑 4% / 7% | 白 5% / 9% | 悬停 / 按下底色 |
| `--brand` | #5856d6 | #8180f5 | 品牌与主操作 |
| `--brand-ink` | #4644b8 | #a5a4fa | 品牌色上的文字 |
| `--brand-soft` / `--brand-line` | 品牌 10% / 32% | 品牌 16% / 42% | 选中底色 / 选中描边 |
| `--ok` `--warn` `--bad` `--idle` | #1f8a4c #a75a00 #d70015 #8e8e93 | #3ddc84 #ffb340 #ff6961 #8e8e93 | 语义色 |
| `--ok-soft` 等 | 语义色 10–14% | 15–20% | 语义色底 |

品牌色同时写入 Arco 的 `--arcoblue-1…10` 与 `--primary-*`，这样 Arco 自带控件自动使用品牌色。开关打开时使用 `--ok`（绿），不是品牌色。

### 2.2 字体

- 正文：`-apple-system, SF Pro Text, PingFang SC, HarmonyOS Sans SC, Microsoft YaHei UI, Segoe UI, Noto Sans CJK SC`，14px，行高 1.5。
- 等宽（`--mono`）：命令、IP、端口、哈希、文件名、参数键。`code`、`kbd`、`.mono` 使用它。
- 数字对齐用 `.num`（tabular-nums），用于计数、时间、序号。
- 标题：页面标题 20px/700、字距 -0.02em；对象名 15px/650；顶栏品牌 15px/650。

### 2.3 形状、阴影、动效

- 圆角：`--r-sm` 6px、`--r` 10px、`--r-lg` 14px；Arco 控件 8px，弹窗 14px，消息条与标签胶囊为 999px。
- 阴影：`--shadow-sm` 控件，`--shadow-md` 下拉与浮层，`--shadow-lg` 弹窗与命令面板。
- 焦点环：`--ring`（品牌色 28% 外发光 3px），所有 `:focus-visible` 统一使用，输入框聚焦同样使用。
- 缓动：`--spring: cubic-bezier(.32,.72,0,1)` 用于滑块、导航条、按钮按压；`--ease-out: cubic-bezier(.22,1,0.36,1)` 用于颜色和入场。
- 入场：内容用 `.enter` 轻微上浮，只改 transform 和 opacity，不引起布局抖动。
- 尊重 `prefers-reduced-motion`：所有动画缩到约 0。
- 控件高度：默认 32px，大号 36px（统一覆盖了 Arco 的 small/default/mini）。

## 3. 应用外壳

顶栏菜单分三组（日常工作：交付 应用 组件 软件库 安全｜AI：AI 知识库 技能 MCP｜管理：IAM 设置），组间 `.tabs-sep` 细线；命令面板（Ctrl+K）按集群、方案、文档搜索。

[main.tsx](frontend/src/main.tsx) 的 `App`：

```
┌────────────────────────────────────────────────────────────────┐
│ topbar 52px sticky，毛玻璃                                       │
│ [Logo Middleware Hub]  [交付|应用|账户]   … [搜索 ⌘K] [外观] [头像] │
├────────────────────────────────────────────────────────────────┤
│ main（路由页面，key=route.name，PageBoundary 包裹）                 │
└────────────────────────────────────────────────────────────────┘
        左下/底部：连接状态胶囊 ConnectivityPill
```

- **顶栏**：品牌标识、主导航（选中项有滑动的底条，`NavTabs`）、命令面板入口、外观菜单（浅色/深色/跟随系统，另有"页面转场动画"开关）、账户菜单（用户名、角色、退出）。
- **主导航**：交付、应用，管理员多一个账户。`新建交付` 属于"交付"这一栏。
- **页面边界**：`PageBoundary` 捕获页面级错误，显示"这个页面出错了"，并提供"回到交付/重新加载"，不让一个页面白屏整个应用。
- **连接状态**：`ConnectivityPill` 显示断网、服务不可达（每 5 秒探测）、恢复后 2.2 秒提示，并触发数据重新加载。
- **首屏状态**：启动中显示居中 Spin；无法连接服务显示重试页；未登录显示 `Login`。
- **页面标题**：`<页面名> · Middleware Hub`。
- **外观**：偏好存 `localStorage["mh-theme"]`（light/dark/system），深色通过 `body[arco-theme="dark"]` 切换，同时更新 `theme-color` meta。
- **无障碍**：页面顶部有"跳到主要内容"链接。

响应式断点（出现在多个样式表）：1500、1280、1100、900、760、700、520px。900px 以下进入窄屏布局：列表与详情改为单栏，向导的分区栏变成横向滚动条，操作按钮固定在视口底部。

## 4. 页面模式

新增页面必须归入以下模式之一，不另创新布局。

### 4.1 主从页（Master–Detail）——交付（集群）、账户

`.md-split`：左侧 340px 列表，右侧详情，高度为 `100vh − 52px`，两栏各自滚动。

- **列表头**：标题加计数，状态分段控件 `Segmented`，筛选面板（范围、排序、分组、应用），已选筛选以 `FilterChip` 展示并可单独移除。
- **列表体**：按"今天/昨天/日期"分组，分组标题粘性定位；每行一个对象：状态点、名称、应用、时间。列表可按方向键移动，打开详情时只替换右栏（路由类型 `pane`，不做整页转场）。
- **详情**：对象标题与状态、关键信息、文件下载、手册（见 4.4）、操作。运行中每秒轮询。
- **空、加载、缺失、错误**：详情有骨架屏 `DetailSkeleton`；找不到对象时显示"找不到这个集群"并给出返回；加载失败给出重试。
- 路由：`#/d/:集群`、`#/accounts/:id`。窄屏下详情全屏，左上角显示返回按钮。

### 4.1a 交付页 = 集群（`deliveries.tsx`、`clusters.tsx`、`outcome.tsx`，1.0.76-dev 起）

顶栏不再有「方案」。「交付」列表的**一行是一个集群**（`GET /api/clusters`）：首次部署和之后的升级、补丁、扩容、缩容方案都在它下面。设计见 [集群与交付重构方案.md](集群与交付重构方案.md)。

- **列表行**：应用图标 + 集群状态点、集群标识、时间（最近一次变动）；第二行"状态 · 应用 版本 · N 次变更"。状态筛选为 全部 / 待执行 / 运行中 / 失败。
- **集群详情**：标题（集群标识 + 状态徽标），元信息（应用版本、系统、机器数、创建时间），下划线页签 **概览 / 方案 N**（`.cl-tabs`）。
  - 概览：占用集群的方案卡片（`.cl-holder`，点击进入该方案）→「要做什么」四个动作（升级 / 打补丁 / 扩容 / 缩容，不可用时置灰并在提示里说原因；集群被占用时全部置灰，原因写在标题旁）→「现在的集群」（当前那份的拓扑图，最宽 620px，旁边是事实列表与偏差说明）→ 安全条 →「经历」（最近 4 份，紧凑时间线）。
  - 方案：完整时间线 `.cl-tl`，最新在上、首次部署在下，每项：类型图标（首次部署 ◆ 灰、升级 ↑ 品牌色、补丁 ✚ 红、扩容 + 绿、缩容 − 橙）、标题 + #序号、状态、"当前"标记、时间、回传人与说明。作废和生成失败的标题划线。
- **一份方案**（`#/d/:集群/plans/:交付`）：顶部面包屑"← 集群的全部方案"和"更早 / 更新"切换；下面是原来的交付详情，标题为"补丁方案 #2"这类名字，元信息下是**回传栏** `.oc`：状态 + 谁何时回传 + 说明；动作为 完成 / 有偏差… / 失败… / 作废…（失败时"继续执行"代替"失败…"），有偏差和作废必须写说明（弹窗，有偏差会用执行中采纳的步骤修改起草）；已完成时只有"撤销回传"，之后已有新方案时不能再改。
- **旧链接**：`#/plans/:交付`、`#/d/:交付` 会跳到该交付所在集群的方案里。
- **被占用时**：概览不显示动作按钮，由未完成方案的卡片说明「完成或作废后可以继续……」。列表行第二行前有历史圆点（`.cl-hist`，每份交付一个，按时间）。页签 `role=tablist`，左右方向键切换，内容 `.cl-pane` 淡入（`prefers-reduced-motion` 时无动画）。
- **类名前缀**：集群 `cl-`、回传 `oc-`、文档 `dc-`、一句话方案 `cpq-`、报告模板 `rpt-`、对话式填表 `fc-`。新前缀先 grep 所有 css，`.ap-` 属于 AI 页面。
- **文档页签**（`#/d/:集群/docs[/:文档]`，`docs.tsx`）：列表按"集群文档 / 变更报告 / 根因分析"分组，每行图标（报/交/变/因）、名称、说明、状态（N 段 AI 草稿待确认 / N 节待填写 / 已完成）、编辑时间；右上"导出 Word…"。打开一份文档是居中的 900px 一栏：面包屑 + 上一份/下一份，标题条（AI 检查、导出 Word），下面是像纸面的预览（封面信息条、标题层级、表格、代码、提示）。要写的节：空时是虚线框（提示 + 自己填写 / 让 AI 起草），AI 草稿有品牌色左条和浅底、"AI 草稿 · 待确认"和"确认"按钮，已写的节悬停才显示编辑 / 重新起草。导出弹窗：勾选文档、合并或分开、未完成提示、左下"封面与页眉页脚"。

### 4.2 目录页（Catalog）——应用

`.store2`：左侧 240px 筛选栏，右侧目录。

- **筛选**：搜索（按 `/` 聚焦）、分类（带计数）、标签、"仅看可部署""仅看我用过"。筛选状态用 `useStored` 存入 `sessionStorage["mh-apps-filters"]`，离开再回来保留。
- **三种视图**：详细 `AppWide`（默认）、网格 `AppTile`、列表 `AppRow`，用分段控件切换；排序为推荐、最近使用、名称。
- **应用图标** `AppGlyph`：按分类着色的圆角方块加简化图形。
- **不可用应用**：显示为静音态并写明原因（`reason`），不能进入新建流程。
- **产品页** `Product`（`#/apps/:id`，整页转场）：顶部横幅（图标、名称、版本、标语、标签、"新建交付"；不可用时显示原因），下方主体分左右：左侧主区按面板切换，右侧 `product-side` 信息栏（规模、系统、架构、离线仓库大小、我的交付数）。五个面板：方案、交付内容、能力与边界、版本与材料、我的交付；没有内容的面板自动隐藏。
- **方案**（`Plans`）：每个方案是一张卡片，带标签（如"推荐"）、规格一行字和角色图形 `PlanGlyph`；点击后以 `?plan=` 进入向导并预填。

### 4.3 工作区向导——新建交付

[Wizard.tsx](frontend/src/Wizard.tsx)。`.wz` 三栏，≥1200px 时显示第三栏：

```
┌ 分区栏 272px ─┬ 当前分区（表单） ──────────────┬ 预览 clamp(340,24vw,440) ┐
│ 返回           │  分区标题 + 说明                 │ 部署图 / 实例 / 将生成    │
│ 应用标识       │  表单行、分组、标签页               │ 阶段 / 提示 / 待完善      │
│ 来源提示       │                                  │                          │
│ 分区导航(编号) │  底栏：上一步 / 下一步 / 生成       │                          │
│ 查看/导入YAML  │                                  │                          │
└────────────────┴──────────────────────────────┴──────────────────────────┘
```

向导**不含任何应用特例**：分区里的字段、分组、标签页、可见性、校验全部来自组件清单（`GET /api/components/:id` 的 schema）和每次修改后调用的 `POST /api/resolve`。

- **五个分区**：集群与规格（标识、操作系统、版本、常用方案；版本旁写明软件库是否备齐）→ 机器（名称、IP、数据盘、是否初始化、控制节点）→ 组件与放置（每个角色选机器；平台自动补的依赖以虚线卡片显示，可“自行指定”）→ 参数（按清单的分组与 `tab` 分标签页，另有“扩展”标签页）→ 入口与证书（添加 HAProxy/Nginx/外部负载均衡，选择代理的端点，证书上传）。
- **解析即校验**：服务端返回的 `issues` 带 `path`，前端据此把问题归到所属分区并支持点击跳转；`warning` 级提示（如“待验证版本”“偶数个 etcd 成员”）显示在预览栏而不阻止生成。
- **预览**：`InstanceGraph` 画出机器与其上的组件实例（自动加入的用虚线），入口以胶囊画在顶部；下面是实例清单、将生成的文件（含软件包仓库 `packages-<系统>.tar.gz`；缺软件包时直接链接到“软件库”页）、部署阶段与步数。
- **YAML 抽屉**：表单与 YAML 是同一份数据；抽屉里可复制、下载、编辑后“导入并应用”，错误来自服务端的严格解析（未知字段会被拒绝）。
- **来源与草稿**：可从“已有交付”（`?from=`）或常用方案（`?plan=`）预填；未改动不保存，改动后存 `sessionStorage["mh-draft2-<应用id>"]`。证书文件不会被保存，需要重新选择。
- **生成前评审**：抽屉汇总机器、实例（含自动加入的及原因）、每个实例改动过的参数（与默认值对照，标注重启）、扩展、上传到各机器的文件；有任何阻断问题时不能生成。

### 4.4 手册页（Runbook）

嵌在交付详情里，[runbook.tsx](frontend/src/runbook.tsx)。数据来自交付里的 `plan.json`（结构化步骤），不再解析 Markdown 文本；可下载的 `00-…04-` 手册由同一份步骤生成，内容一致。

- **篇章**：环境准备、部署、功能测试、入口测试（有入口时）、清理，横向切换，内容按切换方向滑入。
- **步骤时间线**：每步一个可勾选的卡片，勾选状态存 `localStorage["mh-run-<交付id>"]`，顶部显示总进度与“继续下一步”。每步显示执行机器、影响标签（只读 / 修改 / 会中断服务 / 不可撤销）、说明、通过标准、要上传的文件（环境准备里的“解包”步骤直接带出该机器的包下载）。
- **终端块** `Terminal`：命令带语法高亮、悬挂缩进换行、一键复制；点击单行可只复制那一行。
- **危险步骤**：`effect: destructive` 的步骤标“不可撤销”并用危险色；需要额外确认的命令（如放弃备份历史）已在命令里带上 `-e discard_all_backup_history=true`，对应的 playbook 缺少这个变量会拒绝执行。
- 被跳过的测试（如单节点没有切换测试）在该篇末尾列出原因，而不是静默消失。

### 4.4a 软件库页

[library.tsx](frontend/src/library.tsx)（页面）、[libindex.tsx](frontend/src/libindex.tsx)（软件源面板、指南抽屉、导入抽屉、添加抽屉）、[libpkgs.tsx](frontend/src/libpkgs.tsx)（软件包列表）、[libtask.tsx](frontend/src/libtask.tsx)（任务进度）。主从页。

**左侧（系统列表）**：每个系统一行，四层信息：系统图标块（apt 系暖色、rpm 系红色）、名称 + 架构小标、变体（如 RHEL / Rocky / Alma）、状态点 + 文字（可生成交付 / 暂无运行环境）和软件包数与大小。名称、变体、状态分行，任何一项都不被截断。

**右侧**：灰色页面底上，标题行之后是一到两块白色面板。每块面板用同样的图标块开头，标题旁是状态胶囊，右侧是这块面板自己的操作，面板之间用间距分开，不再把所有内容平铺在同一个底色上：

- **标题行**：系统图标块、名称、变体 · 架构 · 包格式 · 是否可生成交付；主操作“添加软件版本”，其余（导入软件包、导出、离线使用指南）收进“更多”。
- **软件源索引面板**（仅 apt 系统）：胶囊（最新 / 需要更新 / 更新中 / 还没有），条目数、软件源数、更新时间，操作“更新 / 导入 / 导出”。**进度出现在这块面板里面**（`TaskCard`），不会插到页面中间；面板底部一行“内网不能联网？……查看步骤”进入离线使用指南。
- **Ansible 运行环境面板**：胶囊（就绪 / 还没有），一行写清 ansible-core 版本、控制节点需要的系统与 Python、离线安装包个数与大小；“查看组成”展开来源包名、文件、SHA256 和每个离线安装包的版本。这些都从运行环境包本身读出（`runtime_info.go`），不是写死的。没有运行环境的系统在这里说明为什么暂时不能生成交付。
- **库里的软件包面板**：标题、数量、文件数与大小；下载进度出现在这块面板里面；组件需要而库里没有的包列在面板顶部的琥珀色条里，带“全部下载”；然后是筛选、排序、全部展开和对象列表。
- **任务进度（`TaskCard`）**：运行中显示标题、当前这一步、百分比、进度条和分组清单（完成、进行中、已跳过、等待、失败各有图标，行内带说明和大小）；结束后收成一行结果（“4 项已更新，7 项没有变化 · 用时 7 秒”），“查看明细”展开清单，“原始日志”再展开文本；失败时清单自动展开并标出失败的一步。后端为每一步发出 `StepEvent`，任务开始前就把全部步骤列出来，进度才有分母。
- **离线使用指南（抽屉）**：从索引面板底部或“更多”菜单打开。两列编号步骤——“在能联网的平台：更新索引 → 添加软件版本 → 导出两个文件”“在不能联网的平台：导入索引 → 导入软件包 → 生成交付”，步骤里写明文件名并带就地按钮，已做的打勾；点按钮会先关闭抽屉再执行。
- **导入（抽屉，索引和软件包共用）**：先讲“这个文件从哪里来”——在能联网的平台打开软件库、选哪个系统、点哪个按钮、会得到什么名字的文件（给出带系统名和日期的示例）、怎么拷过来，并附命令行写法；然后是拖放选择区（选错类型当场提示改用另一个入口）；再写“导入时会检查什么”。成功显示导入了多少，失败给出原因和该怎么办。
- **软件包列表（对象列表）**：每行一个“软件包@版本”，被哪些组件使用（胶囊）、依赖个数与大小、入库时间；可筛选（软件包名、依赖包名、组件名）、排序；**点开一行就地看到它的全部依赖包**（名称在上、版本在下、大小在右，本体高亮），以及来源、文件数、“只导出这一项”；文件缺失或损坏标红；可勾选导出、可删除（删除前说明哪些组件会因此不能生成）。
- **添加软件版本（抽屉，左右两栏）**：左栏搜索（打开即聚焦，输入后 160ms 出结果，↑↓ 选择、Enter 打开）；右栏是选中的软件包——过渡包（描述含 Transitional）先提示真正的程序在依赖里；然后是“选择要下载的版本”标题和**直接可见的单选列表**（最新的在上，带“最新”“已在库”和大小；各版本来自不同渠道时才逐条标渠道：系统自带版本 / 软件更新 / 安全更新 / Percona 官方源，来自同一渠道则在标题旁说一次），默认显示 4 个，其余“显示全部 N 个版本”，↑↓ 切换；再是三个数字（软件包数 / 合计 / 还需下载）加“已在库 / 需下载”比例条和依赖清单。底部托盘收集下载清单。窄屏改为单栏。
- **状态**：加载骨架、空库（直接给“添加软件版本 / 导入软件包 / 离线使用指南”三个入口）、搜索无结果、依赖找不全、已完整在库、索引缺失、更新失败。
- **软件源**（管理员，抽屉）：当前生效的源列表（内置 / 自定义 / 已停用）和自定义 YAML 编辑器；按 `id` 覆盖内置源以改用内网镜像。
- Ubuntu 与 RedHat 系 9 用同一套界面：两者都有软件源索引面板、同样的添加抽屉和任务进度；不再有依赖 Docker 的“获取软件包”抽屉。

### 4.2a 应用目录的三种视图

不留大块空白：

- **网格**：所有应用排成一个连续网格（不按分类各起一行，否则每组一两张卡片会空出大半行），卡片上写着分类。卡片中部有方案就显示方案，没有方案显示前三条能力要点，同一行卡片高度一致。
- **列表**：名称与说明之后一列是能力要点（一行）和方案数、标签，再是分类与规模、状态、新建。窄于 1280px 时隐藏这一列。
- **详细**：每个应用一条：上面一行是图标、名称与状态、一句话说明、标签，中间是前三条能力要点（窄于 1100px 时隐藏），操作（新建、详情）在同一行右侧；下面一条分隔线后，左边横排“从方案开始”（每个方案一个可点的格子），右边是“我的交付”（最近三份）。没有方案也没有交付的应用不画下半部分，条目更紧凑。窄屏上下堆叠。

### 4.4b 部署连线图（InstanceGraph）

交付详情、新建向导的预览共用 `InstanceGraph`：机器是卡片，组件是卡片里的胶囊（“组件名 · 角色中文名”，如“PostgreSQL · 主库”），数据流是机器之间的连线。连线只来自两处，界面不认识任何具体产品：组件清单里声明的 `flows`（复制线带箭头，同步为绿色、异步为灰色；成员互联为橙色点线并在两端画点）和负载均衡的 `fronts`（品牌色，入口到后端）。每条线是一条“车道”，带短标签（WAL、Raft），虚线沿数据方向流动，复制线和入口线上另有光点沿线移动；开启“减少动态效果”时只保留静态线。主库所在机器描边高亮；下方图例列出每种线及“同步/异步”。窄栏用堆叠布局（车道在左、入口在右），宽屏预览用并排布局。旧交付的存档里没有 `flows`，详情接口按当时提交的规格重新算出补上（只补展示字段）。

### 4.4c 组件工作台（`workbench.tsx` 等，`#/components/<名>/edit/<页签>`）

管理员改组件的整页，不在主从页里：页头（返回、名称、保存状态、修订、检查、试生成、发布…、更多）粘在顶栏下，下面是页签栏（概览 / 版本 / 参数 / 角色与关系 / 入口与密钥 / 部署步骤 / 测试与清理 / 文件 / 源码），再下面是内容。

- 表单页签内容最宽 920px，不铺满；文件与源码页签占满宽度并用视口高度（`calc(100vh - 52px - 125px)`）。
- **列表编辑器**是统一的形式：一行折叠的条目（标题、标签、灰色副文）、点开显示字段网格；右侧上移/下移/复制/删除按钮悬停才出现；底部整行的“添加某某”。有问题的条目边框变红并带数字徽标，页签上带红点计数。不要为某个清单字段另造一套布局。
- 字段宽度三档（1/4、1/2、整行，12 列栅格），窄屏 1/4 变 1/2、1/2 变整行。必填字段旁有“必填”小标。提示文字在字段下方，不放进 `<label>`（否则它会混进控件的可访问名称）。
- **不要用 `<label>` 包 Arco 的 Select**：点击会被 label 再派发一次，下拉开了又关（试生成里的“方案”下拉因此点不开，已改为 div）。表单字段的标签是普通文字，点它会聚焦控件。
- 保存是自动的，状态点：绿=已保存、橙=有未保存/保存中、红=失败或冲突；冲突时给横幅并说明没有写入。
- 检查结果、试生成、修订都是**右侧抽屉**（不遮挡页头），试生成抽屉宽 980px、内有分段控件（概览/拓扑/步骤/手册/文件与差异/Ansible 检查）；差异用统一的 `Diff`：绿底加、红底减、灰色省略号。
- 发布是一个小对话框：变化清单（可展开逐行差异）、修订说明（200 字）、有错误时按钮禁用并说明；草稿过期时必须勾选确认才能覆盖。
- 编辑器用 CodeMirror 6，配色全部用页面变量（浅色/深色随页面）；错误行有行号旁的标记和波浪线。
- 懒加载：工作台与指南是单独的包（约 680 kB），只在进入时下载，不拖慢其它页面。

**组件页（`compview.tsx`）**：一整页而不是页签，信息按使用顺序排：版本（各系统能否生成）→ 部署流程（六个阶段连成一条，后面是各阶段的步骤，描述最多两行）→ 参数（按分组，可就地展开收起，前两组默认展开，收起的组仍列出里面有哪些参数）→ 验证与清理 → 入口与关系 → 能力与限制 → 修订（管理员）→ 清单源码（默认折叠）。右侧一条随页面固定的栏：着色的拓扑小图（`TopoArt compact`，客户运维的组件画“客户端 → 负载均衡 → 后端”并说明平台不安装它）、角色/数据流/提供/依赖/端口速览、本页目录（随滚动高亮当前部分）。窄于 1100px 时右栏移到顶部，目录隐藏。

**组件图标与颜色**：`glyphs.tsx` 是唯一的图标库（40×40 白色线条画在着色圆角方块上，线宽与界面一致）和色板；`AppGlyph` 先看传入的 `icon/color`，再查目录登记（`registerStyles`，目录和组件列表加载时登记，所以各处只传 id 即可），最后按分类默认。选择器 `StylePicker` 带三种尺寸的预览。**横幅拓扑图 `TopoArt`** 完全由组件自己的角色、数据流和推荐方案画出：每个角色一行机器，复制/互联的数据流是流动的虚线；界面里没有任何产品特例。

**表单控件是直角**：企业场景下输入框、下拉框、标签输入框保持直角，下拉列表也用 2px 圆角与它对齐；不要给 Arco 输入类控件加大圆角。

**抽屉/对话框不挤页面**：Arco 打开时会给 body 设 `width: calc(100% - 滚动条宽)`，而本应用的滚动条在 `<html>` 上且已预留，结果页面左右抖一下；`theme.css` 里把 body 宽度固定为 auto。

指南页 `#/components/guide`：左侧目录（≥980px）+ 正文 760px；步骤用带编号圆点的列表，代码块用等宽字体并带文件名标题。

### 4.4d 手册的现场执行记录

手册（`runbook.tsx`）的进度保存在服务器：勾选 = 完成；每步下面的“记录结果或粘贴输出”展开一个小表单（完成/失败/跳过、备注、输出）。有记录的步骤在步骤里显示一条带左边线的记录（绿=完成、红=失败、灰=跳过），输出默认折叠、可复制。失败的步骤圆点变红，“下一步”变成“失败，处理后重试”，顶部按钮变为“回到出错的一步”。分段控件末尾多一个“执行记录”页签（时间线，新的在上）。交付列表的副行与详情的元信息显示“现场 x/y 步，n 步失败”。详情右侧“生成记录”里把生成过程折叠成一行（行数与用时），展开才看。

### 4.4e 安全页（`security.tsx`，`#/security[/<交付>]`）

主从页：左边按“需要处理 / 没有待处理漏洞 / 没有漏洞库，无法判断”分组列出所有已生成的交付，每行写严重程度计数（只显示有的）；顶部一行写各系统漏洞库的数据日期，没有数据时用警示色并可直接点开。右边是一份交付：一句结论（“3 个待处理的已知漏洞”或“没有待处理的”）加严重程度计数，筛选（全部 / 中危及以上 / 高危及以上、是否显示已判断的），然后**按软件包**列出（严重度、包名、已装版本 → 目标版本、软件源索引里有没有修复版本），点开才看每条通告（编号链接、标题、CVE、修复版本）和判断。页脚固定写数据来源、日期和局限。严重度用统一的徽标：严重（实心红）、高危（红底）、中危（琥珀底）、低危（灰底）。“漏洞库”抽屉里每个系统一段：状态、数据日期、来源与校验情况、联网更新 / 导出 / 导入，以及内网平台的三步做法。交付自己的页面里有一行“安全”摘要，点进来看详情。

### 4.5 命令面板

`⌘K / Ctrl+K` 打开 `Palette`：分组为"操作"（为每个可用应用新建交付）、"前往"、"最近交付/交付"、"应用"、"偏好"（切换外观、退出）。支持关键词匹配（含英文关键字）、上下键与回车，关闭后焦点归还。

### 4.6 登录

左右两栏：左栏品牌与产品文案（含插画 `HubArt`），右栏登录表单（"使用平台账户继续"）；窄屏只保留表单并在表单上方显示品牌。错误在表单内联显示（`role="alert"`）；401 会话过期时回到登录页并提示"登录已过期"。

## 6. 交互约定

- **键盘**：`⌘/Ctrl+K` 命令面板；`n` 为首个可用应用新建交付（不在输入框、无弹层时生效）；`/` 在应用页聚焦搜索；`Segmented` 支持方向键；`Esc` 关闭面板和抽屉。`typing()` 判断是否在输入中，单键快捷键不得在输入时触发。
- **转场**：用浏览器 View Transition。路由深度（列表 0、对象 1、新建流程 2）决定方向：`forward` / `back` / `swap`；主从页内切换对象为 `pane`，不做转场。返回时恢复原滚动位置，进入新页回到顶部。用户可在外观菜单关闭转场；不支持或系统减少动态时自动关闭。
- **轮询**：有任务运行时列表每 2.5 秒刷新，详情每 1 秒；页面可见时每 30 秒刷新；标签页重新可见立即刷新；进入"交付/应用"页刷新一次。
- **会话**：所有非 GET 请求带 `X-CSRF-Token`；401 触发统一回调，回到登录页。
- **复制**：`copy()` 优先用 Clipboard API，失败回退 `execCommand`，成功给"已复制"消息。
- **消息**：`Message` 胶囊条；错误统一用 `err()`，显示 4 秒。
- **持久化**：草稿、筛选用 `sessionStorage`（随标签页）；主题、转场、手册勾选进度用 `localStorage`。

## 10. 页面切换不抖动

- 根元素始终预留滚动条的位置（`html { overflow-y: auto; scrollbar-gutter: stable }`）。有的页面整页滚动、有的只在面板里滚动，不预留时页面宽度会差一个滚动条，顶栏和居中的内容会左右跳。
- 页面数据按请求路径在本标签页里缓存（`shared.tsx` 的 `fetchCached` / `cached`）：回到去过的页面直接画出上次的内容，后台再刷新；同一请求同时发起只发一次。
- 主从页在宽屏上没有选中项时，直接画默认那一项（不等地址改写后再画第二次）；软件库在取概览的同时就去取默认系统的软件包。
- 骨架屏延迟约 220ms 才显示（`useDelayed`），快的加载不会闪一下骨架。
- 新增样式类名要带页面或组件前缀：`skip`、`main` 这样的通用名已被外壳使用，撞名会把元素拉成整屏高或挤成竖排（两次都发生过）。
