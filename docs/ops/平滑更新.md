# Middleware Hub 平滑更新

生产入口使用 middleware-store store supervise --config /绝对路径/config.json。
入口进程负责 TLS 和浏览器连接；业务子进程仅监听私有 Unix socket。
正常发布只能替换业务二进制并向入口发送 SIGUSR2，不能终止入口或业务进程。
每次发布新版本前，必须同步更新 `internal/server/main.go` 中的 `version`、`currentReleaseDate` 与 `platformReleaseNotes` 公告时间轴条目（推荐使用 `scripts/release.ps1` 自动处理），并运行 `TestVersionEndpointIncludesReleaseNotes` 确认公告版本与当前构建一致。

执行：python3 deploy/ops/update-hub.py --root /data/dazhong-vdi/middleware-hub-run --binary /绝对路径/新版本/middleware-store

入口先等待在途请求（包含 AI 流式回答）和后台任务完成。等待期间继续服务；切换期间新请求在入口等待，禁止重放 POST。旧进程退出后才启动新进程，避免同时修改共享状态。启动失败恢复旧二进制。更新脚本超时或退出不能强杀进程；查看 hub.log 判断排队、成功或回退。

浏览器无需自动刷新。服务保留带哈希的旧静态资源，供旧页面继续加载动态模块。当前未设置自动清理；清理前须确认旧版本页面已不再使用。

组件数据迁移或数据库破坏性变更必须独立评估兼容性；此脚本不在运行中的请求旁执行迁移。入口自身、操作系统重启或服务器故障不属于业务平滑更新，需要维护方案。首次从旧版 serve 切换 supervise 必须在 AI 和任务空闲时进行，不能假称旧入口已具备无中断切换能力。
