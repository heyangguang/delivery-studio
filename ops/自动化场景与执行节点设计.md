# 自动化场景与执行节点设计

日期：2026-11-11。基于 1.0.243-dev 实现复查。
状态：1.0.244-dev 接入改造已验收并上线；以下保留 1.0.243 的场景审计和后续完整设计，不代表所有设计项均已开放。

本轮已实现：独立管理机与集群内执行机、目标随交付授权、堡垒机安装目标 Agent 后配置指定来源的 SSH 公钥、逐项准备检查、按集群隔离目录与软件源端口、不可改写的执行机及检查证据，以及对应向导和技能。管理机与目标当前要求相同 OS/架构；下载的执行器是 Linux x64。

尚未开放：无 SSH 的 Agent 本机执行、现场中继、网络域与重叠 IP、多并发容量、凭据轮换/退役全流程、跨步骤依赖求解。这些不能由“Agent 已连接”推断为可用。既有离线组件仍须验证并发布 automatic 能力后，才有可选自动步骤。测试范围和发布结果见《自动执行接入验收-1.0.244.md》。

## 1. 必须纠正的产品边界

平台管理交付、执行计划和结果；执行节点是负责运行任务的现场机器；目标机器是实际承载 PostgreSQL、Redis、Nginx 等组件的机器。三者不能用一个 controller 字段混为一谈。

- 独立执行节点：安装在集群外的管理机器。经过授权可服务多个交付、多个集群，不计入数据库节点数，不成为数据盘初始化或数据库安装目标。
- 集群内执行节点：从交付目标机器中选择一台安装执行器。这台机器同时具有执行与业务角色，数据库主从身份仍由部署方案决定。
- 两种方式使用同一个执行引擎、组件契约和结果模型。位置与授权分开：集群内节点默认服务本集群，跨集群复用也必须有明确授权；独立节点不是获得任意主机权限。
- 节点位置和目标接入是两个独立选择。目标接入支持设计为：已有 SSH 连接、逐机 Agent 协助建立授权 SSH 信任、Agent 本机执行。拿不到目标登录密码不等于不能自动化；拿到了凭据也不代表必须逐机安装 Agent。1.0.244 提供集中执行与 Agent 配置 SSH 信任；Agent 本机执行仍未开放。
- 交付方式分清两个维度：产物是执行包还是仅配置；执行包由平台自动执行还是现场手动执行。不能为了自动执行另写一套组件或重复创建交付。

## 3. 按使用场景设计

### 3.1 管理员先接入执行节点，还没有任何交付

可以独立登记节点，填写名称、部署位置、所属环境；节点连接后报告自身系统、架构、版本和连接状态。此时不要求用户先虚构一个集群、抄写未来所有 IP。节点接入不等于获得部署权限。

后续交付选择节点时，管理员已有的环境/集群授权或本次明确批准的目标授权才生效。普通交付用户不能因为能选择节点就扩大它的权限。

接入引导必须回答：在哪里安装、能否连接平台、连接后下一步是什么。配置未保存时提示继续接入；丢失凭据可以轮换，旧凭据失效；有任务的节点退役必须先处理在途任务。不能删除执行历史。

### 3.2 创建 PG/Redis/Nginx 的新交付

用户先选方案和真实目标机器。执行方式作为一个清晰的步骤：

1. 自动执行：选择已有独立执行节点，或选择本次集群中的机器接入。
2. 手动执行：生成同一套版本固定的执行包与手册。
3. 仅出配置：只在组件具备该能力时提供，不显示部署完成入口。

自动执行的目标主机直接来自这次交付。页面同时列出“由谁执行”和“影响哪些机器”，不出现第二套要求手填相同 IP 的表单。没有合适节点时解释原因并保留交付填写内容，从当前流程接入后回来继续。仅打开页面或切换执行方式不产生脏草稿。

### 3.3 一台独立节点管理多个集群

每份交付使用自己的工作目录、组件快照、库存清单、连接配置、密码/证书引用和日志目录。相同运行器与软件包可以按摘要缓存，但不能覆盖其他任务需要的版本。

节点页面显示正在执行什么、排队什么、占用多久，以及“因某个任务占用机器而等待”。并发能力必须由节点明确上报和平台限制；单并发节点诚实显示排队，多并发经隔离验证后开放，不为追求并行绕过主机/集群锁。队列按确定的先后规则调度。

同一节点使用不同客户的凭据必须严格隔离。网络不通或权限不覆盖的交付不列为可用。支持多个隔离网络里的重复内网 IP，机器身份不能只用地址。若多个记录实际指向同一物理机器，也要统一资源占用。

### 3.4 管理机与目标机器系统不同

分别确认执行节点 OS/架构和目标 OS/架构，选择对应运行器及软件包。节点的 Python、运行目录和缓存设置不等于数据库的数据目录、挂载点。

安装仓库的提供位置与目标来源配置必须明确；仓库端口、目录、修订不能被另一集群覆盖。可以采用经过验证的集中材料服务或逐机分发，但不能沿用“每份交付都在同一管理机抢同一端口”的假设。

未支持的平台组合在预检中明确阻止，不能仅下载一个标为 Linux 的二进制就认为环境兼容。

### 3.5 客户网络不方便连接

按接入方式检查实际链路：集中 SSH 检查执行节点到平台、执行节点到目标主机；逐机 Agent 检查各 Agent 到平台或现场协调节点，按任务需要检查跨机通信。需要材料服务时再检查目标到材料源的连通性；不能只用节点心跳证明数据库可访问。

连接配置包括地址、端口、用户名、提权方式、凭据引用，按实际支持能力提供跳板机等选项。使用现场凭据或平台受控凭据库时，AI 只看引用与能力，不获得原始密钥。主机指纹确认属于接入检查。

首次安装执行器本身仍需要已有的管理通道：有授权且网络可达时才能远程引导，没有时提供现场安装包/命令。输入 IP 不代表浏览器已具备远程安装能力。完全隔离场景使用同一交付的离线执行与结果导入，不宣称实时回传。

#### 3.5.1 凭据托管在堡垒机，运维可以登录但拿不到密码

这是基础接入场景，不能要求用户导出堡垒机里的密码。运维人员通过已有堡垒机会话逐机安装 Agent；若堡垒机提供已授权的批量作业功能，可以批量安装。平台生成绑定环境、预期主机身份和短有效期的单次接入凭据/安装包，Agent 验证平台或现场协调节点证书，接入后使用每台机器独有的身份。不得在所有主机共用长期注册令牌或分发同一把私钥。

首次安装必须有实际的本机安装与执行权限。只有普通终端会话、没有必要的服务安装或提权权限时，显示具体缺项，由现场管理员完成；Agent 不能凭空获得 root。目标不必访问公网，可以主动连接可达的现场协调节点，由它转交任务与结果。若协调节点充当中继，仍需校验每台 Agent 的身份、目标范围和结果归属。

接入完成后根据客户允许的访问方式提供两条执行路径：

**Agent 协助建立 SSH 信任，集中执行。** 适合不能拿到密码、但允许执行节点经授权连接目标 SSH 的环境，也是复用现有集中式 Ansible 的路径：

1. 选择负责执行的独立管理机或集群内机器，以及本次明确授权的目标。
2. 在执行机本地生成本环境/授权范围专用的密钥，私钥留在执行机；平台/协调服务分发公钥和目标用户信息。
3. 目标 Agent 校验任务范围，在获准的本机账户安装公钥，保留原有 authorized_keys，并记录归属、指纹、作用范围和撤销方式；不自动修改 sshd 策略或授予无边界 sudo。
4. Agent 通过已认证通道回传本机 SSH 主机公钥，执行机据此验证目标身份，再实际测试连接、执行身份和必要权限。
5. 检查通过后才允许集中运行部署步骤。页面分别显示“Agent 已连接”“SSH 信任已配置”“连接已验证”，不能将公钥写入成功当作连接可用。
6. 免密默认只建立执行机到本次目标机的方向。备份等组件确需目标机互访时，组件声明具体来源、目的、账户与用途，单独纳入计划；不生成全机器互信。
7. 密钥到期、轮换、撤销、节点替换都要保留记录并重新验收。若采用 authorized_keys，过期需要实际移除托管公钥；不能只在平台改状态就声称访问已失效。

**Agent 在本机执行，不建立 SSH 信任。** 适合不允许机器间 SSH 或不允许增加 SSH 登录通道的环境。Agent 领取属于本机的受控任务和材料，本地运行并回传结果；中央仍统一编排跨机顺序与检查。授权的自动化 Agent 通道也是运维访问通道，需符合客户允许的接入方式，不能被当作绕过堡垒机控制的默认手段。

本机执行后端必须明确任务位置、需要的材料/凭据、运行用户、跨机依赖、全局只执行一次的任务、串行切换和聚合成功判定。不能把同一份多机 playbook 简单复制到每台 Agent 同时运行。现有组件仅在验证支持该后端后开放；组件作者使用同一语义契约，由平台生成合适执行方式，避免复制三套 PG/Redis 实现。

目标接入页面逐机展示主机名、地址、身份、Agent 连接/版本/权限、SSH 连接方式（如使用）、准备缺项。已有机器和 Agent 按经过核对的身份关联，不能仅凭相同 IP 自动合并。允许同一交付有 SSH 与 Agent 接入的目标，但只有平台与组件支持的混合编排才能启动，否则在选择时明确限制。

### 3.6 已经部署好的集群接入自动执行

选择现有集群与已有交付，核对当前配置、主机身份、目录、凭据及版本。接入不会重跑首次安装、初始化数据盘或重新生成已有密码。

用户选择这次目的：只做健康检查、修改配置、升级、扩容、缩容、备份或恢复。生成对应范围的计划。旧交付不可自动执行时，显示具体步骤的缺项；经兼容性检查创建可执行修订，保留旧记录，不把原有成功全部清零。

部署目标与实际运行状态分别保存；没有现场探测证据时标注最后确认时间，不能把模板角色或历史配置当作实时主从状态。

### 3.7 自动步骤中间需要人工操作

例如 PG + 人工配置云 ELB：部署与健康检查可以自动完成，在“配置 ELB”处等待人工；显示所需地址、端口、检查方式。用户完成后先验证入口，再继续后续步骤。

本场景使用交付中的人工任务和入口约束，不重新引入用户已要求删除的“已有 etcd”等外部组件入口，也不声称已有云 ELB 连接器。

故障切换、恢复演练等有中断影响的测试单独选择和确认；普通健康检查不连带触发。组件可以混合自动/人工步骤，但必须标明边界与继续条件。

### 3.8 某一步失败，需要修复继续

页面首先说明“哪一步、哪台机器、已做了什么、还没有做什么”。保留成功步骤和失败尝试，给出与状态对应的操作：

- 准备受阻且尚未启动：补材料/改连接后重新检查，不要求核实一个不存在的现场进程。
- 明确失败且进程状态确定：查看日志、请求 AI 排错、提交修复，再验证或重试该步骤。
- 已启动但状态不明：核实原节点及目标进程，不能直接换节点重复执行。
- 修复后继续：验证前置条件和必要依赖，只继续已审核的剩余步骤；若执行范围或配置变化则展示新的差异供确认。

AI 的新需求、现场修复、组件改进维持三个不同记录入口。现场修复不必等待组件发布；组件修复发布也不自动更改其他客户集群。会影响长期行为的配置需在验证后固化到本集群目标配置，临时命令要有临时标记。

### 3.9 断网、网页关闭、平台升级、执行节点故障

网页只是观察与控制入口，关闭不停止现场进程。平台更新维持兼容协议，不要求一切执行节点立即升级。执行器自身升级先排空/暂停新任务。

断网完成当前已授权步骤后本地保留证据，恢复再补传；后续没有授权不启动。界面展示连接状态与执行状态两件事，不把离线当作失败，也不把旧绿色状态当作本次成功。

节点丢失、令牌泄露、换机、退役要有独立操作。换执行节点需确认原任务状态、可访问相同凭据材料、前置检查通过；不能在未知状态下自动接管数据库写任务。

### 3.10 改组件、扩容、目录改变与报告

组件发布只产生可用修订；当前执行固定版本。采用更新时展示真实受影响的步骤。扩容自动带出新增主机并检查授权，缩容时明确移除操作仍需作用于旧机器。

数据目录从 /data 改为 /srv/data 是迁移需求，不是可以直接覆盖的普通输入框。执行器工作目录与目标数据目录不同。缺省 /data 与显式 /data 的等价补全不应误判为数据库迁移。

报告首页说明本次目的、集群方案、目标机器、执行方式、执行节点、实际完成范围、失败/未完成事项。详细证据保留修订、每次尝试、机器结果、时间、原始日志入口。人工、导入和自动验证来源不能混淆，旧修订结果也不能直接算作新修订通过。

## 4. 前端主流程

交付页是业务主入口，执行节点页是管理员管理入口。

`选择方案与目标机器 → 选择执行方式和执行节点 → 检查并准备材料 → 审核操作范围 → 执行/人工处理 → 验证与报告`

每一步必须回答一个问题：

| 页面 | 用户需要知道的内容 | 主要操作 |
| --- | --- | --- |
| 选择执行方式 | 谁负责执行、目标有哪些、哪个节点适合这份交付 | 选独立节点/集群内节点，或手动执行 |
| 准备检查 | 每个目标的网络、登录、权限、平台匹配、材料、目录是否就绪 | 运行只读检查；按具体缺项补齐；有权限且已确认时准备材料 |
| 确认计划 | 这次安装/修改/重启什么，哪些步骤复用，哪些需要人工 | 确认范围与影响，不自动加入未确认的依赖 |
| 执行页面 | 当前任务、当前主机、耗时、输出、下一步、等待原因 | 暂停后续、处理失败、人工接管、核实状态 |
| 结果与报告 | 这次实际完成什么、凭什么确认、还差什么 | 查看证据、导出报告、处理跟进事项 |
| 执行节点管理 | 节点类型、环境、连接、能力、授权、队列、维护状态 | 接入、授权维护、轮换凭据、暂停接单、升级、退役 |

仅有节点心跳不得显示“环境就绪”。暂未执行、准备受阻、正在执行、等待人工、暂停后续、失败、状态待核实、已验证、不适用必须分别说明。查看某步骤与实际运行某步骤使用不同标记。

## 5. 实现结构与兼容约束

以下名称是设计用语，不表示已新增 API 或 schema。

- Environment/Host：环境与稳定机器身份；地址是连接属性，不是全局唯一身份。
- ExecutionNode：节点身份、安装位置、平台能力、容量、连接与维护状态。IP 不能替代节点身份。
- ConnectionProfile：SSH/提权/跳板配置及凭据引用，与交付参数分离。
- HostAgent/Enrollment：逐机 Agent 身份、绑定环境与机器、接入凭据的生命周期、连接路径、安装权限、执行能力和版本。中央执行与目标本机执行可以由同一软件的不同角色承担，但角色和权限必须显式区分。
- AccessBinding/TrustGrant：每个目标选用的 SSH 或 Agent 通道；公钥信任记录包含来源、目的、账户、用途、指纹、配置/验证状态、轮换和撤销证据。私钥不进入 AI、页面或目标机分发。
- ExecutionBinding：交付选择哪个节点、采用何种方式、凭据及材料绑定。改变绑定不改变数据库主从角色。
- PreparationResult：固定检查对象及版本，保存逐机检查、缺项、处理状态与有效时间；运行前再次确认关键条件。
- Run/Attempt：固定选择、修订、真实执行位置、作用主机、依赖证据和每次尝试。现有快照与事件记录沿用并版本化扩展。
- Material/Runtime：按版本/摘要标识，区分节点运行依赖与目标软件，清理不能删除在用材料。

编译器显式区分 executor、target、材料源、需要访问数据库的验证角色。controller 旧语义需要审计迁移，不能全局搜索替换；组件里的 localhost、delegate_to、run_once、密码路径、仓库绑定均纳入校验。

旧交付继续保留原包、手册和运行记录。要改执行位置时创建经校验的新执行绑定/必要修订；展示实际差异。新旧节点按协议能力匹配，不让旧节点领取无法理解的新任务。

平台与执行器都校验实际作用范围。组件声明不能扩大授权；AI 提案也不能跳过用户本次执行确认。新增普通参数继续通过公共契约生成 UI、校验和传参，避免 PG/Redis 各写例外。

## 6. 实施顺序

1. 先拆开执行位置、目标机器、材料/密码位置；完成独立/集群内两种执行方式、连接与材料检查、运行器版本隔离、旧交付兼容。将通过堡垒机逐机接入 Agent、免密码公钥配置与验证纳入基础场景；Agent 本机执行需单独通过组件兼容验收，不能以安装成功替代执行能力。这些都按业务场景交付，不把未实现能力写入线上宣传。
2. 接通交付内的选择、准备、执行与结果页面；节点权限维护、队列与占用、人工关卡、故障处置与恢复必须能操作，不以设置页有卡片代替业务闭环。
3. 将组件能力细化到方案/步骤；补齐并验证 PG 常用方案、Redis 常用方案、Nginx 接入、公共流程和报告。同步更新应用内 AI skills、工具参数和后台校验。
4. 按下列业务矩阵验收后上线。定时巡检和备份作为明确的后续功能，不与独立执行节点这种基础场景混为可延后事项。

## 7. 必须通过的验收矩阵

用隔离的管理机与目标机器验收，记录具体软件/系统版本、执行计划、真实日志和报告；不在客户现有集群尝试初始化、切主或恢复。

| 场景 | 必须得到的结果 |
| --- | --- |
| 独立管理机部署 PG 原生主从/Patroni | 管理机不进入数据库/数据盘目标；主从与依赖符合所选方案；逐机验证通过 |
| 集群内机器执行 PG 单机/主从 | 同一台机器的执行与业务角色清晰；不要求额外机器；目标作用范围正确 |
| 同一节点先后/并发服务 PG 与 Redis | 运行器版本、凭据、软件仓库和日志不串用；未开放并发时显示真实队列 |
| 同一节点服务不同 OS/架构 | 支持组合使用正确运行器和目标包；不支持组合在运行前明确阻止 |
| Nginx/etcd 等组件接入 | 遵守同一契约，不修改执行器源码添加组件专属逻辑 |
| 两个隔离环境使用相同 IP | 不误判同一资源、不串凭据、不越权；同一真实主机别名仍正确互斥 |
| 节点先接入、交付后创建 | 不要求虚构集群；交付选择后授权明确；目标无需重复手填 |
| SSH 不通/端口不对/凭据或 sudo 不足/缺材料 | 未启动业务命令；展示具体缺项；处理后重新检查可继续 |
| 现有集群接管后只改一个参数 | 不重装、不初始化数据盘、不重新生成密码；原记录保留 |
| 自动部署 + 人工 ELB | 明确停在人工作业；确认与入口验证后继续；不伪造自动完成 |
| 步骤依赖未满足 | 展示依赖及缺少证据；未经确认不能偷偷加入前序写操作 |
| 只改 A 的私有文件 | B/C 无真实依赖时复用结果；涉及共享依赖则显示具体原因 |
| 第 5 步失败 | 保留前 4 步；修复/验证/继续有入口；重试新增尝试且范围不扩大 |
| 平台更新/关闭网页/断网/重复提交 | 不因此重复启动写操作；状态真实，日志补传，报告无重复证据 |
| 执行器崩溃/换机 | 不自动重派未知写任务；核实、重新绑定、材料检查和继续可完成 |
| 扩容、缩容、数据目录变更 | 新旧目标及授权准确；迁移作为显式计划，不靠默认值覆盖 |
| TLS/TDE 关闭及部分人工步骤 | 未启用/人工确认/自动验证样式和报告来源一致，不重复列项 |
| 报告与旧修订 | 摘要能说明实际完成范围；证据可追溯，旧结果不冒充本次通过 |
| 节点轮换凭据/维护/退役 | 旧凭据行为符合策略，在途任务有明确处理方式，记录不丢 |
| 只能通过堡垒机登录、没有目标密码 | 通过现场安装接入 Agent，无需导出登录密码；已授权目标的信任配置与实测结果可见 |
| Agent 已连接但 SSH 策略禁止登录 | 不显示 SSH 就绪，不自动放开 root/sshd；可用的 Agent 本机执行或人工路径明确 |
| 客户禁止机器间 SSH，使用 Agent 本机执行 | 不写 SSH 公钥；跨机任务顺序、run_once/串行/汇总语义正确；未适配任务不能启动 |
| 只授权执行节点到两台目标机 | 仅配置两台目标；不增加第三台或目标间互信；原有 authorized_keys 保留，私钥不分发 |
| Agent 接入令牌复用/主机身份不符/权限不足 | 拒绝错误绑定或提权；同 IP 不误关联；说明具体处理方式 |
| 目标无法直连平台但可连现场协调节点 | 通过授权中继登记、领任务及补传证据，身份和结果不混淆；无可用链路时提示离线方式 |
| 撤销/轮换 SSH 信任，或更换执行机 | 实际托管公钥移除/轮换与连接验证有证据；只改平台状态不算完成 |

本机临时文件任务、HTTP 接口测试和截图检查仍然有价值，但只能证明对应层面的行为，不能代替这张表里的多机部署与恢复验收。

## 8. 接入向导与执行边界（本轮补充）

本节是完整目标设计。1.0.244 已实现的接入范围以本文开头和《自动执行接入验收-1.0.244.md》为准。设置页、交付页和 AI 必须使用相同的能力信息；未实现的执行方式不能以可点击选项冒充可用能力。

### 8.1 两个选择，不能揉成一种“节点类型”

第一个选择是“由哪台机器负责执行”：独立管理机，或从本次交付的机器列表中选一台。第二个选择是“怎样连接这些目标机器”：已有 SSH、Agent 配置授权 SSH 信任、Agent 本机执行。前者不决定后者；例如，集群内执行机也可以管理通过 Agent 接入的其他目标。

创建交付时只填写实际业务机器；独立管理机不进入 PG/Redis 节点数，不出现数据盘初始化开关。目标机器、地址、方案和目录直接从当前交付读取。接入独立管理机只填写管理机身份与可达地址；选择集群内机器不再要求重复填写 IP。

“新建交付 → 选择执行节点”与“设置 → 接入节点”使用同一个接入向导。可以先登记执行节点再创建交付，但未分配范围的节点只能回传自身信息，不能领取部署任务。跨客户网络不能仅用相同集群名/IP 匹配节点。

页面上固定展示两个不同区域：

- 执行机器：安装位置、系统/架构、工作目录、连接状态、正在运行的交付。
- 目标机器：来自交付的机器、业务角色、接入方式、权限检查、材料检查和待处理事项。

执行器工作目录、目标数据目录、离线软件源目录分别展示。不能将一个“目录”输入同时用于这三个用途。

### 8.2 堡垒机接入要走完的流程

1. 平台根据交付列出待接入机器，生成每台机器独立、短期、单次的接入配置。配置绑定预期身份；不得要求用户提交堡垒机密码、私钥或管理员会话。
2. 用户通过现有堡垒机会话传入已校验的安装包，检查系统、架构、服务安装/提权权限和允许的通信链路，再安装 Agent。只有 SSH 的环境允许不装目标 Agent。
3. Agent 主动连接平台或可达的现场协调节点。接入令牌仅用于登记，登记成功后使用逐机身份；重装、克隆机器、重复使用令牌和主机身份不符须重新核对。配置中不得默认关闭 TLS 校验。
4. 平台列出已核对的执行机、目标、登录用户和用途，由有权限的人批准建立所需连接。允许客户要求每台目标本地确认；批准不能由普通交付用户或 AI 扩大。
5. 若允许 SSH，由执行机生成专用密钥，目标 Agent 安装公钥、回传 SSH 主机公钥；随后从执行机实测网络、身份和权限。私钥不经过平台、目标 Agent、AI 或安装包。
6. 若禁止机器间 SSH，使用已适配的 Agent 本机执行任务。该模式不安装 SSH 公钥、不修改 sshd 策略；未适配的多机任务必须标出阻塞原因，不能偷偷改成 SSH。
7. 只有接入、授权、实际连接、运行依赖、离线材料和步骤前置检查都通过，才进入执行确认。接入 Agent 不自动运行部署，也不自动初始化磁盘。

首次安装 Agent 所需的系统依赖、安装包与校验材料要能通过堡垒机会话或批准的文件渠道送达。不能依赖尚未建立的 SSH 信任下载 Agent，也不能依赖尚未启动的数据库离线仓库安装 Agent。全离线安装包与在线安装要分别验证。

### 8.3 接入与执行使用两套状态

| 对象 | 必须区分的状态 | 页面操作 |
| --- | --- | --- |
| 目标接入 | 待安装、待核对身份、已连接、已断开、已停用 | 安装说明、核对身份、诊断连接、重新接入 |
| SSH 信任 | 待批准、待写入、公钥已写入、连接已验证、待撤销、已确认撤销 | 审核授权、查看实际检查、轮换、撤销 |
| 执行准备 | 未检查、检查中、缺少条件、已就绪、检查已过期 | 按机器/项目查看缺项、重新检查 |
| 步骤尝试 | 未启动、准备受阻、执行中、等待人工、暂停后续、失败、状态待核实、验证通过 | 补条件、日志、人工处理、核实、明确重试或继续 |

Agent 心跳不等于 SSH 已通；公钥写入不等于权限可用；命令退出不等于验收通过。三者不得复用一个绿色“就绪”。

离线目标上的公钥未实际移除前只能显示“待撤销”，不能显示已撤销。需要立即吊销时，必须有执行机停用及客户现场撤销措施；移除 authorized_keys 也不代表已经结束的或仍存活的 SSH 会话自动失效，要另行核实。SSH 公钥安装/移除需有专用标记、原条目保护、并发修改处理和本地结果回传。

从登记到执行绑定都要记录配置版本。主机地址、账户、证书、节点身份、授权范围、执行器版本或材料摘要改变后，相关准备检查失效；不能继续沿用之前的“已就绪”。

### 8.4 现有组件如何共用这套能力

组件继续定义做什么、在哪些业务角色执行、前后置条件、文件/参数依赖与结果。连接账户、凭据、节点授权、缓存和断线处理归平台执行层。PG、Redis、Nginx 不各写一套 Agent 接入代码。

执行契约需要表达执行位置、跨机顺序、只运行一次的任务、串行数量、人工关卡、所需权限/材料和结果关联。平台从同一份计划生成集中执行与经过适配的本机执行；未声明或无法识别的 localhost、delegate_to、run_once 和控制机路径依赖应导致明确的兼容性提示，而不是推测安全。

旧 controller 不能全局改名：密钥生成与读取必须在同一受控位置；配置生成、数据库任务和只读验收可能分别在执行机/目标机；离线源服务要独立指定来源与端口。切换执行机时不能重新生成数据库已有密码，不能将执行机加入 managed/mw_data 主机组。

公共参数编辑器继续支持新增普通参数、说明、条件和校验并联动表单。新增执行协议、权限类型或跨机调度语义属于引擎能力，必须先实现校验与执行支持；不能靠在公共 YAML 中增加任意字段就获得未实现的权限或执行能力。组件发布页按当前方案/版本列出“可自动执行、需要人工、缺少兼容条件”，不让作者仅勾选 automatic 就绕过检查。

### 8.5 回传和报告

报告以“本次做什么、影响哪些机器、实际完成什么、还差什么”为第一页内容。执行机位置、接入方式、所选组件方案、修订及时间随本次执行固定，不能在导出时用最新设置替换历史信息。

- 每次尝试关联步骤、目标身份、执行身份、快照、开始/结束时间、返回码、前后置检查、日志位置和证据来源。
- 准备检查、公钥配置、业务步骤与人工 ELB 确认分别留证，不能把“接入成功”计为“数据库部署完成”。
- 断网时日志/结果本地持久化，空间不足须展示并在安全边界停止领取新任务；不得为了补传失败自动重跑数据库写操作。时钟不一致时依靠尝试 ID 与序号排序，并区分现场时间与平台收到时间。
- AI 可以基于证据写摘要和待办，不能补造成功记录。失败后现场修复与组件长期修复仍分别关联，不覆盖原尝试。
- 关闭网页、平台更新、报告生成不会改变已授权现场任务。升级 Agent 本身要先停止接单并处理在途任务，保持协议版本兼容。

## 9. 实施与放行清单

以下是交付顺序与上线门槛，不表示这些功能已完成。

1. **执行位置解耦**：目标机器、执行机、密码位置和软件源分别建模；独立/集群内两种方式共用编排。验证安装任务绝不会因 local 连接误跑到独立管理机。
2. **接入闭环**：先完成已有 SSH 的逐机只读准备检查，同时补齐堡垒机逐机安装、身份核对、授权公钥配置/撤销。执行入口直接带入目标清单，取消重复手填范围。
3. **Agent 本机执行**：实现并验证跨机顺序、全局一次、串行切换、依赖和聚合检查。禁止把相同多机 playbook 同时发给所有 Agent。没有完成这个门槛时，明确显示该方式尚不可用。
4. **异常与报告闭环**：准备受阻不记为未知写操作；未知状态不重派；人工关卡、修复、继续、日志补传和报告来源一致。
5. **上线检查**：按第 7 节矩阵验收，再加上下面的补充项。同步更新平台 AI skill、工具能力和界面；平滑更新平台，不打断已存在的 AI 会话。

补充验收：

| 场景 | 必须验证 |
| --- | --- |
| Agent 初装时没有 Python、SSH 信任或离线仓库 | 安装检查明确依赖和离线材料，无循环依赖，不先运行部署 |
| 独立执行机切换、旧集群已生成密码 | 引用正确的原材料/凭据，不生成另一套密码，不改数据库目标 |
| 克隆机器带着旧 Agent 身份、重装或 IP 复用 | 阻止静默重复绑定，交付与结果不串到另一台机器 |
| SSH 公钥被用户同时修改、目标离线时撤销 | 保留用户条目；未获得实际移除证据前显示待撤销 |
| 多份交付使用同一管理机的软件源 | 摘要、目录、端口和版本互不覆盖，目标只收到所属计划材料 |
| 预检通过后修改授权/地址/执行器版本 | 相关预检失效，再次确认之前不能使用过期就绪状态 |
| 日志磁盘不足、时钟偏差、重复事件/延迟补传 | 不把数据丢失当成功、不重复运行；证据归属和事件顺序稳定 |
| 同一交付同时使用人工、SSH、Agent 步骤 | 顺序和授权一致，人工关卡确实暂停；未支持组合不能启动 |
