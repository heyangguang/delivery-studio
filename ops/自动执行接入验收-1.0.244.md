# 自动执行接入验收 · 1.0.244-dev

日期：2026-11-11。发布状态：已平滑上线 1.0.244-dev，线上只读检查通过。

本轮交付独立管理机、集群内执行机与目标 Agent 的 SSH 接入流程。完整场景设计见《自动化场景与执行节点设计.md》；本文只记录实际实现与验证范围，不将后续设计算作已实现。

## 用户流程

1. 新建交付，在“机器”中填写实际业务机器，再选择由集群内机器还是独立管理机执行。独立管理机不会计入数据库机器数，不接受数据库角色或数据盘初始化。
2. 在“设置 → 执行节点”接入执行器。登记时只填写执行机信息，不重复抄写目标机器。节点首次连接不等于已获准部署。
3. 生成交付后，在“现场执行 → 选择自动执行步骤”选择节点。本次目标直接读取交付，由具备执行节点管理权限的人明确授权。
4. 选择已有 SSH，或者通过堡垒机在目标机器安装 Agent。目标 Agent 配置本执行机、当前集群所需的 SSH 公钥，不要求导出堡垒机密码。
5. 检查执行机身份、系统、交付材料、运行环境及每个目标的身份和 root 权限。检查失败显示逐项原因，缺项或过期不能继续。Agent 已连接、公钥已配置与实际 SSH 验证分别显示。
6. 选定本次步骤并确认集群名后才执行。结果保留执行机身份、准备证据、每次尝试、机器结果和日志，汇入交付报告。

## 实现边界

- 独立管理机为每个集群使用独立目录 `/root/middleware-executions/<集群标识>/middleware-automation` 和软件源端口；运行器不仅核对版本摘要，还核对当前集群目录，避免串用密码。更新包应用命令也使用同一目录。
- 执行机不进入业务主机组；PG、Patroni、Redis 的业务测试改为在业务主机运行。PG 跨机备份、切换等测试仍依赖业务机之间的 SSH，已增加前置检查；执行机到目标的公钥接入不代表目标机器已经互信。
- 目标 Agent 的安装配置逐机生成，首次登记有效期 30 分钟，绑定主机名、地址和机器身份。私钥保留在执行机，平台只分发公钥。撤销只清除本次托管的公钥，保留其他登录配置；目标离线时等待实际撤销回执。
- 新节点必须提供与交付版本、授权、Agent 身份一致且未过期的准备检查。准备失败且命令未启动，与现场执行状态未知分别处理。
- 报告使用执行发生时固定的节点名称、位置和连接方式；后续更名不会改写历史。准备检查不计为数据库部署成功。
- 旧交付、执行记录、组件草稿继续保留。组件发布不触发已有集群同步或执行。

## 当前仍不支持的场景

- Agent 本机运行任务且完全不使用 SSH、现场中继、隔离网络域及重叠 IP 尚未开放。当前 Agent 是授权 SSH 接入；目标必须可连平台，执行机必须可连目标 SSH。
- 下载的执行器为 Linux x64；当前独立管理机与目标要求相同 OS 版本和架构，仍需 root 和目标 Python 运行依赖。不同系统/架构与普通用户提权不能假定可用。
- 单节点串行领取任务；未开放多并发容量配置、完整凭据轮换/退役、跨步骤依赖自动求解。
- 已有 PG/Redis 离线组件没有被直接改成 automatic。自动能力仍需组件作者提供步骤超时、可验证完成条件并通过发布检查；旧离线交付不会因此直接出现可执行的自动步骤。
- 本轮没有完成真实多机 PostgreSQL/Redis 的安装、切换、恢复演练。这些需使用明确的验收环境逐方案验证，不能用语法检查或接入成功替代。
